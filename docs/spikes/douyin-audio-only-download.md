# 抖音纯音频轨下载（2026-08-15）

## 起因

`cdn-download-concurrency.md` 已证明：下载是拆账号的唯一大头，CDN 按客户端聚合限速
（抖音 0.7 MB/s），**并发越高聚合越低** → 提速只剩一条路：**少下字节**。

ASR 只需要 16k 单声道语音，却在下整片 1080p 视频。本轮验证上游是否给了更省的源。

复现脚本：`douyin_bitrate_probe.py`（探字段）、`douyin_audio_only_verify.py`（验内容）。

## 1. `aweme.video` 里有三级可选源

同一账号（`https://v.douyin.com/LIVJSlsfTTU/`）实测：

| 视频 | `play_addr`（**当前用的**） | 最低视频档 `bit_rate[-1]` | `bit_rate_audio` 纯音频 |
|---|---|---|---|
| v0（929s） | 37.3MB | 17.9MB（540_2_1） | **5.6MB** |
| v1（543s） | 23.8MB | 10.3MB（540_2_1） | **3.3MB** |

- `bit_rate` 是档位数组（3-4 档），每档自带 `play_addr.url_list`（各 4 个 CDN 节点）
  和 `data_size`——**下载前就知道字节数**。
- `play_addr` 既不是最高档也不是最低档，是平台选的默认档；最低档约为它的 **48%**。
- `bit_rate_audio.audio_meta.url_list` 是纯音频流（`media-audio-*`），约为 `play_addr` 的 **14%**。

## 2. 纯音频轨是原声人声，不是 BGM

这是方案能否成立的证伪点。同一条视频（359s，即 `cdn-download-concurrency.md` 的抖音 v2）
两路各跑一遍完整 `transcribe`：

| 源 | 下载 | 下载耗时 | 整条 transcribe | 转写字数 |
|---|---|---|---|---|
| 纯音频轨 | **2.2MB** | **5.2s** | **24.1s** | 2300 |
| 整片视频 | 41.8MB | 44.5s | 62.5s | 2277 |

两份文本开头逐字一致（差异仅 ASR 标点/空格，如「三十个 AI 产品」vs「三十个AI产品」）：

> 今天跟大家分享个事儿啊，就是前两天呢我在社交媒体上突然收到一个红杉资本的投资人的消息…

**结论：`bit_rate_audio` = 视频原声轨。19x 字节、8.6x 下载提速、2.6x 端到端提速。**
音频直链用默认下载头即可拉取，无额外防盗链。

## 3. 覆盖率只有 ~40%——必须留回退链

同一页 8 条里只有 3 条带 `bit_rate_audio`。且该字段**形状不稳**：既出现过 dict，也出现过
list，缺失时是空 `{}`（与 `_resolve_sec_user_id` 的 str/dict 分歧同类，两种都要吃）。

故落地形态是三级回退，而非替换：

```
bit_rate_audio（~14% 字节，覆盖 ~40%）
  → bit_rate 最低档（~48% 字节，覆盖 ~100%）
  → play_addr（现状，兜底）
```

按覆盖率加权，10 条 133MB 的实测样本 → 约 43MB（**降 68%**），下载墙钟 ~200s → ~65s。

## 4. 落地结果：同一账号 TOP10 改造前后实测

`account_transcribe_bench.py`，同一账号同一批 10 条，改造前后各跑一次：

| | 改造前 | 改造后 |
|---|---|---|
| 转写段总墙钟 | 505.2s | **255.8s** |
| 成功条数 | 9/10 | **10/10** |
| 含 scrape 合计 | 519.6s | 276.1s |

单条对比（秒）：929s 视频 131.5→84.4、359s 视频 191.1→**47.5**、448s 视频 268.5→115.0。
转写字数逐条相差 <1.5%（ASR 非确定性），内容等价。

两处质变而非量变：

- **改造前有 2 个 CDN 节点各卡满 120s `total_timeout` 才降级**（同一条视频白烧 240s）。
  字节数降下来后没再出现——慢节点在小文件上也能在超时内跑完。
- **3951s（66 分钟）那条改造前必然撞满 300s 墙钟失败，改造后 255.8s 成功**（25023 字）。
  它现在是整批的关键路径：去掉它这批只要 ~115s。长视频要不要进 TOP10 是产品问题。

## 5. 顺带发现：DashScope 体积上限

整段 wav（359s）不切片直接喂 `recognize_wav` → `400 InternalError.Algo.InvalidParameter:
Multimodal file size is too large`。生产链路靠 `slice_audio` 切片绕开，但该错误**不在**
`_PERMANENT_MARKERS` 里，被当瞬态重试了 3 次（白烧 45s）。应补进永久标记。
